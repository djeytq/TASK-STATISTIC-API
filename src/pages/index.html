Task Statistics API

Open the live demo →

01

What is this API?

The Task Statistics API is a RESTful backend that turns a simple array of tasks into a professional PDF report.

You send a list of tasks (id, title, description and progress status), the API validates and processes them, builds a statistical report with PDFKit — summary cards, a pie chart with the distribution of statuses and a detailed table of every task — and answers with a application/pdf file ready to be downloaded by the browser.

📄

PDF generation

Beautiful reports generated server-side with PDFKit: header, status cards, pie chart and task table.

🌐

CORS enabled

Any frontend — local or remote — can call the API. No extra proxy needed.

🧩

Typed & modular

TypeScript models, controllers, services and helpers with a clean layered structure.

🚀

Ready-made frontend

No frontend yet? The API ships with a demo page you can serve and use right away.

Quick start — clone the repository, run npm install, then npm run dev. The server will start on http://localhost:8083 (or the PORT defined in your .env file).

Project Structure

The codebase follows a classic layered architecture: Route → Controller → Service → Model, with a dedicated helper for the PDF engine.

# folder structure (simplified) task-statistic/ ├── src/ │ ├── app.ts # Express entry point + CORS + middlewares │ ├── routes/ │ │ ├── index.ts # Master router mounted at "/dev" │ │ ├── task.routes.ts # Task endpoints (/dev/task/*) │ │ ├── docs.routes.ts # Documentation page (/dev/docs) │ │ └── demo.routes.ts # Demo frontend (/dev/demo) │ ├── controller/ │ │ └── TaskController.ts # Handles HTTP requests & responses │ ├── service/ │ │ └── TaskService.ts # Validates & maps payload into Tasks │ ├── model/ │ │ └── Task.ts # Task entity (id, title, description, progress) │ ├── helper/ │ │ └── generateTaskPDF.ts # PDFKit generator (summaries, chart, table) │ ├── interfaces/ │ │ ├── Progress.ts # "TO_DO" | "IN_PROGRESS" | "IN_TEST" | "DONE" │ │ └── generatePDF.ts # Contract for PDF generators │ ├── pages/ # This documentation page │ └── tests/ # Ready-made frontend demo ├── .env # PORT=8083 ├── package.json └── tsconfig.json

How a request flows

Browser
fetch POST → Route
task.routes → Controller
TaskController → Service
TaskService → Helper
generateTaskPDF → PDF
response
  • Routes declare the HTTP endpoints and delegate to the controller.
  • Controller reads the body, calls the service, sets headers and sends the response.
  • Service validates the payload (must be an array) and creates typed Task instances.
  • Helper generates the PDF buffer using PDFKit with status colors, summaries, a pie chart and a table.

05

How to create a PDF

The method that generates the PDF statistics is POST /dev/task/generate-report.

1. Send the payload

The body must be a JSON array of tasks. Each task accepts:

  • id — number (optional, falls back to the position + 1)
  • title — string
  • description — string
  • progress — one of TO_DO, IN_PROGRESS, IN_TEST, DONE
[ { "id": 1, "title": "Create login page", "description": "Auth screen for the mobile app", "progress": "IN_PROGRESS" }, { "id": 2, "title": "Fix responsive navbar", "description": "Fix overflow issues on small screens", "progress": "DONE" }, { "id": 3, "title": "Design empty states", "description": "Nice placeholder for empty lists", "progress": "TO_DO" } ]

2. The response

On success the API answers with 200 OK and the file as a binary application/pdf attachment:

HTTP/1.1 200 OK Content-Type: application/pdf Content-Disposition: attachment; filename="tasks.pdf" Content-Length: <bytes>

If the body is not an array of valid tasks, you get a 400 Bad Request with a JSON error message instead.

3. Test it without a browser (cURL)

curl -X POST http://localhost:8083/dev/task/generate-report \ -H "Content-Type: application/json" \ -d '[ {"id":1,"title":"Create login page","description":"Auth screen","progress":"IN_PROGRESS"}, {"id":2,"title":"Fix navbar","description":"Responsive issue","progress":"DONE"} ]' \ -o tasks.pdf # The generated report is saved as "tasks.pdf"

06

How to connect a frontend to this API

Connecting your frontend is one fetch call. The only detail that surprises people: the endpoint returns a PDF file, not JSON — so you must read the response as a Blob and trigger the download in the browser.

This is exactly the approach used by the frontend in the src/tests folder of this project. Step by step:

1
Send the tasks as JSON

Use fetch with method: "POST" and the header Content-Type: application/json. The body is the tasks array serialized with JSON.stringify.

2
Check the response

If response.ok is false, the server answered with an error — read the text and throw it so you can show it to the user.

3
Read the PDF as a Blob

Use await response.blob() instead of response.json(). The payload is a binary PDF file.

4
Create a temporary URL

window.URL.createObjectURL(blob) generates a link the browser can use to access the blob in memory.

5
Trigger the download

Create a temporary <a> element, set its href to the object URL and its download attribute to "tasks.pdf", then click it programmatically.

6
Clean up

Remove the temporary link and release the blob memory with window.URL.revokeObjectURL(url).

Complete example (used in src/tests/script.js)

// tasks = your array of tasks, e.g. // [{ id: 1, title: "...", description: "...", progress: "IN_PROGRESS" }, ...] async function generateTaskReport(tasks) { try { // 1. Send the tasks as JSON const response = await fetch( "http://localhost:8083/dev/task/generate-report", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(tasks) } ); // 2. Handle errors if (!response.ok) { const errorText = await response.text(); throw new Error( `HTTP ${response.status}: ${errorText}` ); } // 3. The response is a PDF file -> read it as a Blob const blob = await response.blob(); // 4. Create a temporary URL for the blob const url = window.URL.createObjectURL(blob); // 5. Create a temporary link and click it to download const link = document.createElement("a"); link.href = url; link.download = "tasks.pdf"; // name of the downloaded file document.body.appendChild(link); link.click(); // 6. Cleanup document.body.removeChild(link); window.URL.revokeObjectURL(url); console.log("PDF generated successfully!"); } catch (error) { console.error(error); alert("Failed to generate PDF: " + error.message); } }
Remember — the route you call is POST /dev/task/generate-report. Full URL: http://localhost:8083/dev/task/generate-report. Because CORS is enabled, this works from any origin.
Why Blob? — If you used response.json() here, it would fail: the server's answer is a binary application/pdf file, not JSON. The blob() method keeps the raw binary data so the browser can download it correctly.

What the demo does

  • Adds, edits and deletes tasks with a modal form.
  • Stores the tasks in memory (tasks array).
  • On Generate PDF, it sends the array with fetch to /dev/task/generate-report.
  • Reads the answer as a Blob, creates an object URL and downloads tasks.pdf automatically.

The source files live in the src/tests folder:

src/tests/ ├── form.html # demo page structure ├── style.css # demo styles └── script.js # fetch + Blob logic (see section 06)
The demo works out of the box because it is served by the same origin (localhost:8083), so no CORS configuration is needed when testing locally. For a separate frontend (another port/domain), CORS is already enabled by the API.
